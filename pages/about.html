About

Software should have an immune system, not just an alarm.

Monitoring tells you something broke. Then a human wakes up, reads a stack trace, guesses a fix and hopes. We wanted to know what happens if the system can protect itself first, fix itself properly, and only ask a human for the final decision.

Protect

Stop user impact first. Diagnose second.

Prove

Adversarial tests and real traffic, not vibes.

Prevent

Find every twin before it becomes the next outage.

The story

Built in four hours, on purpose.

TraceZero started as a hackathon question: could we make the most stressful part of running software, the incident, feel boring?

The constraint shaped the design. One Python process, one HTML file per page, no Docker and no build step. Patches are hot-swapped in memory so the demo can't restart under us, and an offline playbook mode means it works with no Wi-Fi.

The bugs in the demo store are deliberately ordinary: a division with no zero check and a string method on a value that can be null. Most real outages look exactly like this.
